# Documentation

The documents are the source of truth for Afterword: the experiment was designed here before any code was written, and the code follows them. This is the full list, in reading order. The project's [README](../README.md) has a shorter one.

1. [`PROJECT-BRIEF.md`](PROJECT-BRIEF.md): the question and why it matters
2. [`SCOPE.md`](SCOPE.md): what V1 is and is not
3. [`LABELING-GUIDE.md`](LABELING-GUIDE.md): what "consequential" means and how ground truth is produced
4. [`LABELING-FIELD-GUIDE.md`](LABELING-FIELD-GUIDE.md): the practical checklist to keep beside you while labeling (the guide and the taxonomy win where they differ)
5. [`TAXONOMY.md`](TAXONOMY.md): comment classes and flags
6. [`PRIORITY-POLICY.md`](PRIORITY-POLICY.md): how classes become priority, and where the review threshold sits
7. [`EVALUATION.md`](EVALUATION.md): how the claims are tested
8. [`CLAIMS.md`](CLAIMS.md): what is being claimed, before evidence exists
9. [`DATA-MODEL.md`](DATA-MODEL.md)
10. [`PRIVACY-AND-BOUNDARIES.md`](PRIVACY-AND-BOUNDARIES.md)
11. [`USING-AFTERWORD-ON-YOUR-ACCOUNT.md`](USING-AFTERWORD-ON-YOUR-ACCOUNT.md): the privacy statement for anyone running Afterword on their own account
12. [`API-CAPABILITY-MATRIX.md`](API-CAPABILITY-MATRIX.md)
13. [`ROADMAP.md`](ROADMAP.md): the stages, their gates, and the status log
14. [`WORKFLOW.md`](WORKFLOW.md): the operating protocol: fresh probe, timing before labeling, labeling sessions, and the weekly routine of the test period
15. [`COMMANDS.md`](COMMANDS.md): the full command reference
16. [`LABELING-AT-SCALE.md`](LABELING-AT-SCALE.md): a future design note for labeling beyond V1 (not V1 scope)
17. [`FUTURE-FEATURES.md`](FUTURE-FEATURES.md): candidate features after the Stage 3 gate, each with a proposed claim (not V1 scope)
18. [`adr/`](adr/): the architecture decision records
19. [`proposals/`](proposals/): changes under discussion, and accepted ones with their evidence
20. [`FRICTION-LOG.md`](FRICTION-LOG.md): the index of the friction log, with the entries in one file per session under [`friction-log/`](friction-log/)
21. [`benchmarks/`](benchmarks/): dated benchmark write-ups, informational only
22. [`BRAND.md`](BRAND.md): how the name and logo are presented
